# chalkery

[![CI](https://github.com/drdickgraysonjr/chalkery/actions/workflows/ci.yml/badge.svg)](https://github.com/drdickgraysonjr/chalkery/actions/workflows/ci.yml)

[English](README.md) | Українська

Chalkery — місце, де лежить крейда: дім для модів Claude Code, які малюють над полем вводу.

Три моди для Claude Code, які малюють смугу над полем вводу. Працюють у терміналі й у вкладці Code десктопного застосунку.

| Мод | Що робить |
| --- | --- |
| [`handoff-relay`](plugins/handoff-relay/README.uk.md) | Кнопка Handoff запускає `/handoff`. Від 180k токенів контексту вона підсвічується. Мод приносить власний скіл `handoff`, тож кнопка працює одразу після встановлення. |
| [`cache-meter`](plugins/cache-meter/README.uk.md) | Показує, скільки ще кеш промпту лишатиметься теплим і скільки коштуватиме перекешування. «Тримати теплим» не дає кешу охолонути. Перед відправкою в охололий великий кеш мод питає підтвердження. |
| [`next-steps`](plugins/next-steps/README.uk.md) | Кнопка «Що далі?» пропонує до трьох наступних промптів. Обраний промпт стає чернеткою в полі вводу, Enter натискаєте ви. |

Моди можна ставити окремо або всі разом. У будь-якому поєднанні вони складаються в одну смугу з тим самим порядком рядків: Handoff, кеш, «Що далі?».

## Вимоги

Claude Code 2.1.289 або новіший. Моди побудовані на function hooks, порівняно новій частині Claude Code, і перевірені на 2.1.289. Старіші версії можуть їх не завантажити: 2.1.96, наприклад, відхиляє їхні маніфести.

Версію покаже `claude --version`, оновлення — `claude update`. Десктопний застосунок оновлюється сам.

## Встановлення

Спершу додайте маркетплейс:

```bash
claude plugin marketplace add drdickgraysonjr/chalkery
```

Усі три моди однією командою. Пак називається primaries: три моди, як три основні кольори.

```bash
claude plugin install primaries@chalkery
```

Або лише потрібний:

```bash
claude plugin install cache-meter@chalkery
```

У десктопному застосунку те саме є в меню Plugins → Add plugin: вкладка Marketplaces, потім Add marketplace. Моди починають працювати з наступної сесії.

Коли виходить нова версія, спершу оновіть каталог, потім кожен встановлений мод:

```bash
claude plugin marketplace update chalkery
```

```bash
claude plugin update cache-meter@chalkery
```

Видалити пак: `claude plugin uninstall primaries@chalkery`. Три моди, які він поставив, після цього лишаються встановленими. Щоб прибрати і їх, виконайте `claude plugin prune`.

## Мова

Моди говорять англійською й українською. Кожен має опцію `language` зі значеннями `auto` (за замовчуванням), `en` або `uk`. З `auto` моди беруть мову відповідей Claude з `/config`, тож одне налаштування діє на всі три. Якщо мову там не задано або модам вона невідома, вони показують англійську. Задати мову явно можна в `/config` або одразу при встановленні:

```bash
claude plugin install cache-meter@chalkery --config language=uk
```

## Скіл handoff

`handoff-relay` приносить скіл `handoff`. Він пише документ для наступної сесії в `.claude/handoffs/` у корені проєкту, а якщо CLAUDE.md проєкту називає іншу теку — туди. Хендофи складаються в ланцюжки: сесія, яка підхоплює документ, називається `<назва> H<N>`, і кожна фаза має свій файл. У десктопному застосунку скіл ще й створює картку, що запускає наступну сесію; у терміналі друкує стартовий промпт, який треба вставити. Якщо у вас уже є свій `/handoff`, кнопка запускає саме його.

## Опції next-steps

Після встановлення CLI повідомить, що частину опцій не задано. Усі вони мають значення за замовчуванням, тому задавати їх не обовʼязково.

| Опція | За замовчуванням | Що робить |
| --- | --- | --- |
| `language` | `auto` | `auto`, `en` або `uk`, як описано вище |
| `minAnswerChars` | `80` | Після коротших відповідей кнопки немає |
| `suggestSkills` | `true` | Пропозиція може бути скілом чи слеш-командою сесії |

## Якщо не працює

**`Unrecognized key: "options"` або `invalid manifest file`.** Ваш Claude Code старіший, ніж потрібно модам. Виконайте `claude update` і встановіть ще раз.

**`primaries` пише `Dependency "handoff-relay@chalkery" is not found in any configured marketplace`.** З маркетплейсом, найпевніше, усе гаразд: один із модів не встановився, а пак повідомляє про це так. Встановіть цей мод окремо, і побачите справжню помилку:

```bash
claude plugin install handoff-relay@chalkery
```

Найчастіше це помилка старої версії, описана вище.

## Для авторів

```
.claude-plugin/marketplace.json   каталог: пак і три моди
plugins/<мод>/                    кожен мод самодостатній, ставиться окремо
plugins/<мод>/hooks/locales/      en.mjs і uk.mjs: усі написи, які бачить людина
plugins/handoff-relay/skills/     скіл handoff і скрипт фаз (python3, з тестами)
plugins/primaries/              пак: лише dependencies на три моди
shared/band.mjs                   договір спільної смуги
shared/i18n.mjs                   вибір мови за опцією language
scripts/sync-shared.sh            копіює shared/*.mjs у hooks/ кожного мода
scripts/check.sh                  запускає всі перевірки, які робить CI
.github/workflows/ci.yml          CI: на кожен push і pull request, і щотижня
```

**Спільна смуга.** Порядок, у якому рушій складає хуки `ui.render` різних плагінів, не задокументований і залежить від способу встановлення. Тому мод не ставить свій рядок над чи під тим, що повернув `next(e)`. Він вкладає рядок у спільний стовпець `prompt-band` на своє місце: Handoff 10, кеш 20, «Що далі?» 30. Чуже, тобто рядок рушія чи мода не з цього репо, опиняється під ними. Мод ставлять і без сусідів, тому `band.mjs` та `i18n.mjs` лежать копіями в кожному. Правити слід `shared/`, потім запустити `scripts/sync-shared.sh`. Перевірка, що копії однакові: `scripts/sync-shared.sh --check`.

**Мови.** У коді мода немає тексту, який бачить людина: мод бере його з `locales/<мова>.mjs`. Нова мова — це ще один файл у кожному моді, рядок у `LOCALES` і шаблон у `shared/i18n.mjs`. Тести кожного мода перевіряють, що в усіх мовах однаковий набір ключів.

**Перевірка.** `scripts/check.sh` запускає все разом: перевіряє маніфести, проганяє тести кожного мода й тести скрипта фаз, звіряє копії спільних файлів, перевіряє версії відносно тегів релізів і ставить `primaries` у тимчасову домашню теку. CI робить те саме на кожен push і pull request на Claude Code 2.1.289, найстаршій версії, яку обіцяє цей README, і щопонеділка на найновішій; якщо щотижневий прогін упав, GitHub надсилає лист. Перевірити один мод:

```bash
claude plugin validate plugins/cache-meter && claude plugin test plugins/cache-meter
```

Тести смуги підставляють сусідні моди окремими плагінами в обох порядках. Тести мови покривають `en`, `auto` без `/config` і `auto` з українською в `/config`.

**Розробка наживо.** Щоб працювати з робочою копією, а не встановленою версією, додайте теки модів у `CLAUDE_CODE_PLUGIN_DIRS` (розділювач — двокрапка). Плагін із такої теки перекриває встановлений з тією самою назвою.

**Випуск.** Підніміть `version` у `plugins/<мод>/.claude-plugin/plugin.json`. Без цього `claude plugin update` у колег не побачить змін, а CI впаде, якщо мод змінився після свого останнього тегу релізу, а версія лишилась та сама. Після злиття позначте реліз тегом із теки мода: `claude plugin tag --push` створює `<мод>--v<версія>`, тег, за яким рушій розв'язує версії залежностей.

**Чек-лист перед релізом.** Саму смугу CI не бачить, тож перед тегом перевірте руками:

1. `scripts/check.sh` проходить.
2. Зі зміненими модами в `CLAUDE_CODE_PLUGIN_DIRS` нова сесія в терміналі показує смугу в порядку: Handoff, кеш, «Що далі?».
3. Те саме у вкладці Code десктопного застосунку.
4. Handoff запускає `/handoff`, «Що далі?» пропонує варіанти, `/cache` показує стан кешу.
5. Якщо перемкнути `language` на `uk`, а потім на `en`, усі написи змінюють мову.
6. У кожного зміненого мода нова `version`.
