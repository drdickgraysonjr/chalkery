# cache-meter

[English](README.md) | Українська

Форк кешової частини cache-keeper з [nateherkai/claude-code-mods](https://github.com/nateherkai/claude-code-mods) (`33a936f`, автор Nate Herk), без дошки, хендофу й режиму запису.

Кожен запит перечитує весь контекст. З кешу промпту це коштує приблизно десяту частину звичайного вводу. Коли кеш спливає (година простою на підписці, 5 хвилин за стандартним TTL API), наступне повідомлення знову записує весь контекст за ціною від 1,25 до 2 звичайного вводу. Мод показує, у якому стані кеш і скільки коштуватиме перекешування.

## Що видно

- Рядок над полем вводу: кеш теплий, остигає чи охолов, і скільки коштуватиме перекешування. На API — у доларах. На підписці — у токенах, бо підписка платить лімітами плану, а не доларами; так само для моделі, цін якої мод не знає. `/cache` додає долари як API-еквівалент. Ліміти плану з'являються, коли якийсь перевалив за 80%.
- **Тримати теплим**: кнопка (`k` у терміналі) або `/keepwarm [години|off]`; що вона робить і що витрачає — у розділі [Тримати теплим](#тримати-теплим).
- Питання перед відправкою в охололий великий кеш (за замовчуванням від 150k токенів): «Надіслати все одно», «Стиснути й надіслати», «Запустити `/handoff`» (якщо він є в сесії) або «Скасувати».
- Сповіщення, коли великий кеш скоро охолоне.

Скільки живе кеш: 60 хвилин на підписці й 5 на API; мод розрізняє їх за тим, чи повідомляє Claude Code ліміти плану після першої відповіді. Далі це уточнює те, що мод вимірює, і сам Claude Code, коли змінюється модель. `/cache` каже, звідки взялося число.

## Тримати теплим

«Тримати теплим» не дає кешу охолонути, поки вас немає. Перед кожним спливанням мод надсилає крихітний запит, який перечитує кеш і цим перезапускає його таймер. За замовчуванням це триває 4 години, максимум 24; `/keepwarm off` чи «Не тримати» зупиняють раніше.

Це не безкоштовно. Кожен пінг перечитує весь контекст: на API це частка ціни вводу, ≈ $0.04 за 200k токенів Opus 5.5; на підписці ті самі токени йдуть у ліміти плану. Годинному кешу підписки потрібен пінг раз на 52 хвилини, близько 4 за 4 години; 5-хвилинному кешу API — раз на 3,5 хвилини, близько 70. На старті сповіщення оцінює, скільки буде пінгів і скільки читає кожен.

Мод зупиняється сам, коли вийшов час, коли пінг записав кеш замість читання (кеш однаково вже охолов), коли пінг лишився без відповіді, і щойно будь-яке вікно лімітів плану дійшло до 90%: пінги не мають з'їсти ліміт, потрібний вашому наступному справжньому повідомленню. Від 90% і вище він не вмикається.

## Команди

| Команда | Що робить |
| --- | --- |
| `/cache` | Стан кешу й налаштування |
| `/cache ttl 5\|60\|auto` | Час життя кешу лише на цю сесію; `auto` повертає те, що показує сесія |
| `/cache guard on\|off` | Питання перед холодною відправкою |
| `/cache big 150k` | З якої кількості токенів контекст вважається великим |
| `/cache alerts on\|off` | Сповіщення перед охолодженням |
| `/keepwarm [години\|off]` | Тримати кеш теплим або перестати |

Якщо `/cache` чи `/keepwarm` уже зайняв інший плагін, команди мода називаються `/cm-cache` і `/cm-keepwarm`.

## Для інших модів

Мод публікує стан кешу в `$.state` як `cache-meter.cache` (див. `types/index.d.ts`). [handoff-relay](../handoff-relay) і [next-steps](../next-steps) читають його, щоб показати ціну своєї кнопки на холодному кеші. Сам cache-meter від інших модів не залежить.
